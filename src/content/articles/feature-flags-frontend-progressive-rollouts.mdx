## Flags in Code: Patterns That Scale

### The Flag Boundary Pattern

Flags should live at feature boundaries, not scattered throughout components.

**Bad: Flags buried everywhere**

```typescript
function PriceDisplay({ price }) {
  const showTax = useFlag('show-tax-breakdown');
  const newFormat = useFlag('new-price-format');
  // Flags buried deep - hard to find, hard to remove
}

function CartItem({ item }) {
  const showDiscount = useFlag('show-discount-badge');
  // Another buried flag...
}
```

**Good: Flag boundary at the feature level**

```typescript
export function PaymentSection() {
  const useNewFlow = useFlag('checkout-new-payment-flow-release');
  return useNewFlow ? <NewPaymentFlow /> : <LegacyPaymentFlow />;
}

// Components below don't know about flags - they're just components
function NewPaymentFlow() {
  // Clean code, no flag checks
}
```

## Closing Thoughts

Feature flags are a deployment tool, not an architecture. They let you separate deployment from release, reduce risk, and ship faster. But they come with overhead — every flag is technical debt until it's removed.

The teams that succeed with flags treat removal as seriously as creation. Ship fast, but clean up after yourself.
